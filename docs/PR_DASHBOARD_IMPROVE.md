## 한 줄 요약

최종 리포트 대시보드를 비전공자도 따라올 수 있는 여러 화면(개요 → 후보 목록 → 후보 상세 → 읽는 법)으로 다시 짜고, 시연 타깃 DemoShop을 **100개 입력점이 그대로 화면의 UI인 실제 쇼핑몰**처럼 만들었습니다. 입력 이름·기본값·GET 폼·응답 동작·정답 데이터는 그대로이고, 크롤 결과도 33개 엔드포인트·100개 입력점으로 같습니다.

## 변경 사항

### 1. 리포트 대시보드 (`src/vulnspider/reporting/`)

- HTML 한 파일 안에서 **분석 개요 / 취약점 후보 / 후보별 상세 / 리포트 읽는 법**으로 이동하는 다중 화면 구조. 메뉴·검색·필터·화면별 인쇄.
- 분석 과정을 단계로 연결(엔드포인트 수 → 입력점 수 → 유형별 후보 수 → 선택된 후보 수), 경로·입력점 소속 지도, 후보 유형 구성 차트, 대표 후보 최대 3개의 **검증 전 확률 vs 최종 신뢰도** 비교.
- 후보 상세에 초기 관찰 근거, baseline/probe 요청 정보, 추가 검증 페이로드·결과, 방어 지침.
- 용어 통일: **상위 취약점 후보 / 최종 신뢰도**(검증이 없으면 검증 전 확률을 그대로 표시). 점수는 분석기 값만 쓰고 리포트에서 재계산하지 않음.
- 후보의 baseline 응답에서 확인되는 DemoShop 표시 번호·이름(`입력점 #069 · 판매자 코드`)을 지도·목록·상세에 표시. 정답 데이터는 참조하지 않음.
- 외부 라이브러리·폰트·이미지 요청 없이 파일 하나로 열림. (ADR-041/042)

### 2. DemoShop 스토어프론트 (`tools/demo_shop.py`, `tools/demo_shop_storefront.py`, `shop.css`, `shop.js`)

- 각 라우트의 **canonical GET 폼이 곧 페이지의 UI**: 카탈로그·검색은 상품 목록 위 필터 바, 상품 상세는 옵션 패널(`id`·`variant`·`tab`·`qty`), 장바구니·주문서는 주문 양식, 나머지 27개 경로는 각 서비스의 조회·등록 양식(경로별 버튼 문구). 서버의 파라미터별 응답 카드(조회 행·반사·DB 오류·검증 경고)는 폼 아래 "조회 결과"로 항상 표시.
- 제출값이 화면에 반영: 목록 필터·정렬·페이지, 상품 전환, 수량·쿠폰·배송비·결제 수단 → 총액. 헤더 검색창은 `/search?q=`로 실제 동작.
- 상품 12개(사진 4장 + 색상 변형 8장)로 브랜드·색상·사이즈·정렬·페이지 필터가 실제로 동작. 옵션 칩은 상품별(신발: 자기 색 × 250–280, 가방: 자기 색 × M/L, 헤드폰·램프: 색 3종).
- **⊙ 입력점 표시** 모드: 100개 컨트롤에 번호·외곽선, 입력점으로 이어지는 화면 요소(검색창·카테고리 탭·상품 목록·상품 탭·페이저)에 `⊙ #001 검색어 q` 태그. `localStorage`로 페이지 이동 후에도 유지.
- 크롤 표면 보호: 칩·페이저·탭은 이름 없는 `type="button"`, 쿼리 붙은 링크 없음, 검색창은 `name`/`<form>` 없음. **상품 데이터는 `/assets/products.js`로 분리**해 상품·옵션·스타일을 고쳐도 라우트 HTML(=응답 바이트=랭킹 특징)이 바뀌지 않음. 스크립트가 없어도 서버 렌더링 상태로 동작.

### 3. 상품 사진 (`tools/demo_shop_assets/`)

- 색상 변형 8장은 `make_variants.py`로 생성: `rembg`(U²-Net/ISNet) 매트로 상품만 분리해 배경·그림자를 그대로 두고 상품만 재채색(블랙·화이트 스니커즈는 검 솔 유지). 1024px JPEG, 합계 약 830 KB. `rembg`는 런타임 의존성이 아니며 없으면 GrabCut 폴백.

### 5. 이번 작업 — 시연용 취약점 검증(PoC) · 대시보드 시각 개편

**(1) DemoShop 실시간 취약점 확인 화면 (`tools/demo_shop.py`)**

- 상위 후보가 실제 취약점임을 비전공자에게 눈으로 보여주는 **PoC 확인 배너**를 추가했습니다. `vs_confirm` 마커가 붙은 요청에서만, 해당 입력점에 보낸 페이로드가 취약 동작을 실제로 유발했는지 판정해 "✅ SQL Injection 취약점이 확인되었습니다" 같은 배너를 응답 맨 위에 그립니다 — 무엇을 보냈는지, 무엇이 증거인지(노출된 DB 오류·삽입된 스크립트 원문·행 수 변화·타인 자원 노출)를 평이한 한국어로 설명합니다. 안전한 입력점에는 "🛡️ 방어됨"과 그 이유를 보여 대비를 만듭니다(SQLi/XSS/IDOR + 하드 네거티브 커버).
- **스캔에 절대 영향 없음**: 마커는 사람이 여는 `/_lab`(크롤되지 않음)의 "🎯 취약점 검증" 링크로만 붙습니다. 마커가 없는 일반 요청 = 스캐너가 보는 응답은 HEAD와 **바이트 단위로 동일**함을 확인했습니다(전 라우트·전 페이로드 diff 0). 확인용 스타일도 확인 화면에만 주입.

**(2) 대시보드 '발표 스토리' 페이지 삭제 (`src/vulnspider/reporting/`)**

- 분석 개요와 중복되던 `#presentation` 화면과 관련 네비게이션·CTA를 제거했습니다. 사이드바는 개요 / 취약점 후보 / 리포트 읽는 법 3화면으로 정리.

**(3) 대시보드 시각 리터치 (`dashboard_assets.py`)**

- "LLM스러운" 인상을 주던 카드 그라데이션·흐릿한 그림자를 걷어내고, 얇고 일관된 테두리(hairline)와 차분한 라운드로 통일. 지표 타일은 상단 액센트 룰 + 더 큰 수치, 발견→근거 스트립은 액센트 스파인 + 단색 집중 단계.
- **한눈에 읽히도록** 후보 표의 각 행을 유형색(SQLi·XSS·BAC)으로 좌측 컬러 레일 처리하고 점수 미터를 두껍게, 후보 상세의 심각도 레일도 4px로 강조. 단일 액센트(teal) 체계로 정리.

## 참고 · 리뷰 포인트

- 랭킹은 응답 바이트에 민감해 HTML이 바뀌면 근소한 순위(소수점 셋째 자리)가 움직입니다. 이 PR로 타깃 HTML이 바뀌었으므로 **`docs/results`(8/30) 수치는 재생성해서 인용**해야 합니다 — `python tools/results_pack.py --top-k 20`. 결과 팩 재생성본과 러너의 시작 불가 회귀(`ModuleNotFoundError: tools`) 수정은 별도 커밋으로 올릴 예정.
- 형 변환 오류를 흘리는 하드 네거티브 3개(`stock`·`qty`·`min_price`)는 검증도 "근거 뒷받침"으로 판정합니다. 알려진 한계로 보고서에 그대로 기술.
- 기본 페이지(`/product`)의 `variant=black-270`은 크롤 baseline이라 상품이 샌드 색이어도 값은 유지됩니다(옵션 칩만 상품에 맞게 바뀜).
